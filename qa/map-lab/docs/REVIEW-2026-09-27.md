# Infrastructure pass review

Scope: NYC source additions, conservative merge/elevation rules, bounded 2D/3D geometry, walking placement/falling, validation UI and regression runner. Main game modules are unchanged. No changes are staged or committed by this pass.

## Findings fixed

- **Area spill:** whole source features and neighbouring OSM vertices enlarged or escaped the selected area. Both views now clip presentation; base terrain uses the selected rectangle.
- **Edge mismatch:** analytic ground bounds differed from Float32 triangle edges. Ground queries use the drawn boundary coordinates.
- **Edge spawn:** automatic spawning could place the walker on/outside the crop edge. Candidate points stay inside the selection; a ground search failure is explicit.
- **Renderer contract:** adding road references made the detail-only builder require an unrelated roads array. Road references are now an explicit optional argument.
- **Surface normals:** bounded geometry lost normals with terrain disabled. Clipping recomputes normals and retains other vertex channels.
- **Height provenance:** normalization overwrote specific dimension attribution and labelled infrastructure offsets as curb measurements. Existing attribution is preserved; display offsets are identified separately.
- **Level confusion:** unresolved bridge/tunnel geometry could be drawn as ground surfaces, especially with merging disabled. Structural height resolution is independent of duplicate suppression; unknown levels remain references.
- **Rail gauge:** corridor width was used as track gauge. Single numeric OSM gauge tags now convert millimetres to metres; unsupported gauge values retain logged estimates.
- **Ground snapping:** a highest-surface query cannot distinguish roofs/decks from ground support. A separate height-limited support index supports falling and underpasses; building undersides are excluded.
- **Stale tests:** source counts, the collapsed coordinate panel, a newly ambiguous details selector and line geometry counted as triangle surfaces broke checks. Tests follow the registry and current UI/geometry contracts.
- **Stale reports:** a previous validation report could remain visible after regeneration. Regeneration/selection changes clear it.
- **Clearance roles:** an early validator compared bridge-road vehicle limits against terrain below that same road. Clearance checks now restrict this comparison to ground-level ways.
- **Runner selection:** misspelled test names could select no tests and appear successful. The runner validates named subsets and records their scope.
- **Stale Help:** hardcoded source rows/counts and ground-only walking descriptions no longer matched implementation. Help, pipeline and physics documentation were updated.
- **Checkbox churn:** NYC visibility changes rebuilt every preview path and merge mask. Checkboxes reuse raw SVG paths and re-resolve selected merge inputs; browser checks cover repeated hide/show cycles.
- **Tree conflicts:** trees inside road/walkway interiors and overlapping generated rows lacked a shared placement rule. Source-preserving exclusions, clear matched positions, row deduplication and logged surface/member IDs now resolve these conflicts.
- **Build progress:** initial generation and benchmark rebuilds now paint a spinner and current stage before each operation. The same stage generator drives synchronous callers and interactive builds; CPU stage timings exclude paint waits. The loader is hidden before frame measurement.
- **Paint cancellation:** aborting a benchmark cancels pending progress frame callbacks, including when a hidden tab stops delivering animation frames. Partial builds release their resources.
- **Coverage labels:** excluded trees were initially counted as missing and absent from the default merge-log filter. Exclusions now have a visible coverage column and appear in changed merge decisions.

- **Ground disagreement:** Road-centreline and bridge-footprint evidence separates elevated spot observations from bare-ground interpolation. Original readings and inferred roles remain logged; the captured Shell Road clearance contradiction is resolved.
- **Coincident surfaces:** Identical raised sidewalk/median footprints with the same level and material role share one mesh while retaining both records. Disabling the median restores the selected sidewalk.
- **Filter semantics:** Disabled sources/categories are removed before matching, so enabled building/tree/road alternatives return. The 3D view uses that selection on regeneration.
- **Instance boundaries:** Transformed instances are clipped at the area edges, while interior instances stay batched. Building cuts receive caps, including courtyards.
- **Validation limits:** Validation now scans every active instance transform and detects positive-area partial surface intersections, including different triangulations.
- **Cap precision:** Quantized cap endpoints could split a shared edge across adjacent rounding cells. Neighbour-cell welding and double-precision intermediate cuts preserve closure; real captured building and primitive cases pass.
- **Terrain test roles:** Edge-clipped props became ordinary meshes and were mistakenly tested as terrain sheets. The test now distinguishes rigid clipped props from draped surfaces.

- **Cached props:** clipped and batched components share placement updates for every source visibility change, including boardwalks and new ground-surface providers; no source-name allowlist controls placement.
- **Approach continuity:** connected ground roads now slope from supported deck edges through available road-height observations to estimated terrain endpoints, preserving way-split topology and the crossing road below. Validation measures actual meshes at the deck boundary.
- **Approach roles:** non-bridge approach surfaces remain available to walking, prop placement and tree exclusions; deck masks keep underpasses separate.
- **Preview masks:** NYC surface paths now honor the same deck masks as their 3D geometry and restore original paths when merging is disabled.
- **Containment gaps:** interval checks against polygon boundaries prevent small holes or concavities from being missed by sampled roadbed containment.
- **Sample conflicts:** all observations in a conflicting projected station group are excluded; an agreeing subset cannot silently become the selected height.
- **Source ordering:** approach traversal and nearest-owner ties use stable road IDs without mutating source order.
- **Seam identity:** validation now samples the selected deck and approach chain; an unrelated overlapping surface cannot conceal a missing join.
- **Spot location:** estimated crossfall now preserves height at the actual observation coordinate instead of treating off-centre measurements as centreline readings.
- **Roadbed splits:** one OSM way can cross successive NYC roadbeds. Exact non-overlapping centreline intervals now profile each provider instead of requiring the entire way to fit in one polygon; overlapping providers remain logged conflicts.

## Generic review corrections

- **Benchmark resize:** the environment observer starts after the caller paints the report-panel layout; actual later resizing/focus changes still invalidate measurement.
- **Grounded structures:** tagged elevated/underground platforms, barriers and props remain references until a role-specific height is supported. No road-deck height is assigned by containment alone.
- **Stale placement:** every source visibility change recalculates rigid prop contact with remaining ground surfaces, including boardwalks.
- **Partial meshes:** a failed multi-polygon surface or road rolls back its earlier geometry and selectable entries without disposing shared materials.
- **Record identity:** canonical geometry plus original attributes distinguish conflicting observations; multipart points have individual IDs and original-record links. Raw snapshots are unchanged.
- **Coverage blind spot:** the benchmark audits drawn ranges, visible material groups, referenced vertices and physical measures; coverage remains an audit rather than a topology-equivalence proof.
- **Stationary replay:** page and CLI share movement validation from scenario requirements. Custom stationary scenarios remain supported.
- **Water semantics:** unresolved OSM and NYC water stay references and are excluded from walking surfaces.
- **Incomplete disposal:** preview, picker, source controls and NYC layers own abortable DOM callbacks; rebuilt layer callbacks are released before replacement.
- **Duplicate clipping:** merge coverage and road approaches share segment/polygon intersection logic and named tolerances.
- **Runner coverage:** the runner discovers regression scripts, includes release isolation, records the quick/full page preset, and runs browsers sequentially under Xvfb.
- **Stale verification:** documentation points to scoped, dated run results instead of claiming historical success from overwritten files.

The follow-up review also checked multipart point identity, independent component recreation, inactive draw ranges/materials, and short walking scenarios. Regression cases live in `tests/review-regression-test.mjs` and `tests/review-ui-test.mjs` alongside the existing feature tests.

## Final review corrections

- **Underground evidence:** ground-height inference ignored `location=underground`. Shared physical-level classification excludes subsurface/tunnel evidence; unresolved relative layers also stay out of ground inference without labelling them underground.
- **Curb conflicts:** contradictory classification or numeric claims could select a curb height by record order. Claims are collected before selection; equal-priority conflicts preserve every record and log that no height was selected.
- **Malformed multipart:** invalid MultiPoint coordinates could abort normalization before per-record error handling. Shared source geometry validation preserves the raw record, logs one error and lets valid siblings generate in both views and terrain sampling.
- **Terrain coverage:** benchmark comparison omitted the separately owned base terrain. Coverage now traverses the complete scene; hidden or changed terrain invalidates comparisons.
- **Outline coverage:** building edge lines lacked feature identity and escaped coverage checks. Every building drawable now carries its source identity; hiding outlines changes measured line coverage without changing solid surface area.
- **Stale schema:** profiling documentation described an older report schema. It now links the current contract and states the limits of geometry coverage and baseline compatibility.

The manual rereview covered data acquisition, normalization/merge/elevation rules, geometry and resource ownership, walking, UI lifecycle, benchmark validity/reporting, regression scripts and documentation. Regression cases cover each correction; unchanged third-party vendor implementations are outside this Map Lab review.

## Data-layering review corrections

- **Negative bridges:** negative OSM layers were incorrectly classified as underground and denied measured bridge profiles; relative ordering is now separate from physical support.
- **Unresolved placement:** roof/overhead locations, floors, indoor tags and malformed layer values could render on ground; they now retain logged reference geometry until placement is supported.
- **Building levels:** underground/unsupported buildings bypassed elevation resolution and could merge with surface buildings or suppress parent volumes; they now remain independent outlines without ground collision.
- **Passage semantics:** a ground-level building passage was treated as an underground tunnel; compatible passages now retain ground geometry, with portal/clearance modelling still outside this pass.
- **Ground evidence:** relative layer alone could act as bridge evidence, and unknown locations could act as ground evidence; both now require the shared physical-role decision.
- **Ramp evidence:** an underground neighbouring road could veto a visible road-height observation or act as a bridge endpoint when contradictory tags were present; approach roles now use the same classification.
- **Diagnostic drift:** clearance and unresolved-join checks ignored tunnel/location/floor rules used elsewhere; they now share ground/bridge eligibility with the resolver.

See [physical-layer rules and primary references](DATA-LAYERING.md). Regression tests cover these findings, including Merge on/off and actual browser generation. The initial targeted scope is preserved locally in `.tmp/map-lab/layer-review-model.json` and `.tmp/map-lab/layer-review-browser.json`; the successful instrumented captured-scene check is in `.tmp/map-lab/layer-review-capture.json`. Subsequent targeted runner outcomes are in `.tmp/map-lab/checks-model.json` and `.tmp/map-lab/checks-browser.json`.

- **Renderer termination:** the captured-scene browser check terminated twice during generation; Chrome reported crash code 133 on the instrumented failure. A subsequent diagnostic run completed generation and all deck-join/geometry checks. The cause is unproven; no retries, recovery path or timeout increase was added. Build-stage heap/timing output and target-crash events now make another failure easier to localize. This remains a verification limitation, not a resolved layering finding.

## Findings left for the rendering/data audit

- **Approach uncertainty:** grades/crossfall and terminal terrain anchors remain estimates. Missing node topology, ambiguous roadbed ownership and unsupported decks cannot produce a fully constrained approach; embankment sides/volume are absent. Seam checks sample the centreline crossing, not every point across its width.
- **Overlap semantics:** partial surface intersections are now visible in validation, but road junctions and deliberate overlays are mixed with conflicting duplicate surfaces. These candidates still require physical-role classification.
- **Collision coverage:** validation does not check general prop-to-prop or building-wall intersections; matching a render rule does not establish survey accuracy.

- **Vertical gaps:** some tracks/decks, station roofs, water levels and tunnel depths lack a supported vertical model. Outlines remain inspectable; measured deck coverage is incomplete.
- **Structure detail:** deck thickness, columns, rock-scale geometry and shore/terrain cutaways are absent. Hydro footprints/elevations currently supply simple surface tops.
- **Primitive estimates:** rail profiles, wall/fence dimensions, boardwalk placement and several prop dimensions remain estimated. Source-derived geometry does not make those estimates measurements.
- **Conservative matching:** overlapping elevated tracks and coastal representations are not comprehensively deduplicated. Same-location evidence alone is insufficient.
- **Physics limits:** the lab lacks general prop/ceiling collision, game movement features and a two-controller comparison harness. Outside-area walking still uses the terrain callback; the crop is a rendering boundary, not a game world boundary.
- **Stage responsiveness:** build stages and explicit validation execute on the main thread. Progress paints between stages; a long individual stage still blocks interaction. No worker pipeline is implemented. Faster generation is deferred at the user's request.
- **Semantic gaps:** unresolved OSM/NYC water and tagged elevated details stay references; standalone closed structures still need physical-role rules, and roof, stair and other recorded fields remain unused. The [feature-family audit](RENDERING-GAPS.md) lists these gaps with source examples.

See [validation](GEOMETRY-VALIDATION.md) for the one-command checks and source-data diagnosis, [infrastructure](INFRASTRUCTURE.md) for source/type coverage, and [physics comparison](PHYSICS-COMPARISON.md) for game integration differences.
