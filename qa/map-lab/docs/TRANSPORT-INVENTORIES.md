# Live roadway, ramp and bridge inventories

NYSDOT's public layers participate in the existing area fetch, source controls, raw exports, source merge and worker rendering flow. The implementation is in the [source registry](../data/map-sources.js), [complete ArcGIS acquisition](../data/arcgis-features.js) and [source normalization](../pipeline/nyc-model.js). Help reads the source and merge registries directly.

| Dataset | What it adds | What it does not establish |
| --- | --- | --- |
| [State Ramp](https://gis.dot.ny.gov/hostingny/rest/services/Geocortex/HDSV/MapServer/7) | Ramp centerlines, interchange codes, DOT road IDs, direction, bridge references and lane/pavement fields | A complete interchange graph, measured ramp grade, deck outline or support coordinates |
| [Roadway Inventory](https://gis.dot.ny.gov/hostingny/rest/services/Roadways/Roadway/FeatureServer/3) | Road/ramp classification, route measures, direction IDs, bridge identifiers, lane, shoulder, median and pavement fields | OSM node connectivity, surveyed deck crossfall or independent agreement from repeated route representations |
| [Bridge Inventory](https://gis.dot.ny.gov/hostingny/rest/services/Asset/NYSDOT_Structures/FeatureServer/0) | Bridge location, span count, structural system/material, recorded length/deck area, ownership and inspection fields | Locations or shapes of individual columns, pier caps, footings, cables, train supports or foundations |
| [2023 National Bridge Inventory](https://geo.dot.gov/server/rest/services/Hosted/National_Bridge_Inventory/FeatureServer/0) | A separate federal bridge point and complete original inspection/structure fields, including span counts, maximum span, deck width, relative vertical clearance and navigation pier-protection code | Individual piers, caps or underside surfaces; an absolute deck grade; confirmed identity with a nearby NYSDOT bridge record |
| [Bridge With Roadway Inventory](https://gis.dot.ny.gov/hostingny/rest/services/Roadways/SMS_Roadway_Inventory/FeatureServer/0) | State bridge BIN to roadway-route relationship, reported latitude/longitude, ramp/mainline class and from/to route measures | A road centerline, measured pavement width/grade, individual support position or proof that two rows share one deck surface |
| [Overhead Sign Structure](https://gis.dot.ny.gov/hostingny/rest/services/Asset/NYSDOT_Structures/FeatureServer/2) | Separately classified sign-asset point, AssetID/SIN, status, edit timestamp and GlobalID | Sign face, gantry span, individual post/footing locations, height or bridge/train support geometry |
| [Height Restricted Bridges](https://gis.dot.ny.gov/hostingny/rest/services/Geocortex/osowscreen_hoocs/MapServer/2) | Bridge point/BIN, carried and crossed features, inspection dates, reported minimum, posted and permitted vertical clearances | Continuous underside or road profile, ramp grade, direction-specific route clearance, individual supports or validated interpretation of zero/high sentinel values |

[NYC DOT Citywide Low Bridges](https://data.cityofnewyork.us/Transportation/Citywide-Low-Bridges/rn6h-i66u) is a further candidate for **relative clearance** under selected limited-access-highway overpasses. Its [published readme](https://www.nyc.gov/html/dot/downloads/pdf/lowbridge_kml_readme_feb09.pdf) lists clearance feet/inches, sometimes by travel direction, and says the inventory is incomplete and excludes local streets. The Socrata asset is a link with no row columns; its GeoJSON API returns HTTP 400 and the linked NYC DOT KML returned HTTP 403 in the 2026-09-29 access probe. It cannot yet be admitted as a reliable live query. This does not supply absolute deck/road elevations, support locations or a complete corridor profile.

The [NYC DOT Bridge Ratings table](https://data.cityofnewyork.us/Transportation/Bridge-Ratings/4yue-vjfc) may add dated ratings and bridge types, but has no verified geographic area filter. Its BIN identity, temporal coverage and join to a geographic bridge record still need validation before admitting it as an area snapshot. It does not publish individual support coordinates or underside surfaces.

All properties and complete layer metadata remain available, including fields not yet interpreted by rendering. Acquisition first fixes the complete intersecting object-ID inventory, then checks every native ArcGIS and GeoJSON batch against it. Native true-curve/Z/M channels are requested and retained beside the GeoJSON used for display. Missing, duplicate or unexpected object coverage rejects the snapshot. MapServer layers can omit `objectIdField`; their declared OID field supplies identity and is explicitly validated. These services can return `objectIds:null` for an empty selection; acquisition accepts that only with the expected ID field and an independent zero-count response, retaining both original responses. An absent ID list or unconfirmed empty selection still fails.

Paired native/GeoJSON properties must also agree field by field, independently of property order. Conflicting values or missing/extra fields reject the combined snapshot. Original requests and successfully decoded adapter responses from rejected or cancelled acquisitions remain separate `acquisitionFailures` evidence in the page result, renderer observation inventory and merge-log download; generation and benchmark downloads also retain that evidence with acquisition timings. This covers ArcGIS, Socrata, LION and incomplete OSM responses. I3S also retains each completely read binary channel before decoding or rejecting a failed sibling channel. Failed network/body reads have no complete payload to retain; rejected evidence is not a usable source snapshot. Low-level failed HTTP attempts are still reported through API errors/retry diagnostics rather than archived as source observations. Incomplete pairs never enter the active source list. This validates paired attributes, not an atomic server snapshot or equivalence of true curves and GeoJSON geometry; each original representation remains available separately.

The roadway and ramp layers advertise `hasZ:true`, but every sampled vertex Z in the captured Coney/Verrazzano areas was zero. This is not evidence of sea-level pavement. Route measures M are retained independently and never treated as height. Horizontal reprojection to longitude/latitude does not establish a vertical datum or unit. Width fields remain in their original properties until their field units and physical meaning are verified; multiplying lane counts by widths would be a renderer calculation.

The bridge-roadway service is an ArcGIS **table**, not a geometry layer. Its reported `Lat`/`Long` fields supply the reference point without interpolation. Acquisition queries a bounded coordinate rectangle, fixes the complete object-ID set, then fetches every field for those IDs and rejects missing, duplicate or out-of-area rows. Original table responses and metadata remain in the observation archive. The [Manhattan sample manifest](SOURCE-SIZES.md#lower-manhattan-2-km-comparison) records 15 rows, including rows classified as ramps. BIN/route IDs and route measures remain relationship fields; they do not create a ramp alignment or deck grade.

The height-restricted service declares `CONDITION_RATING` as `esriFieldTypeSingle`. Its native JSON prints values such as `6.516`, while its GeoJSON prints the corresponding float32 value `6.51599979`. The shared adapter now requires exact equality after float32 conversion **only for fields declared Single**; all other fields still require exact equality, and both original values remain preserved. The first live Coney and Manhattan attempts rejected this apparent mismatch; a repeat completed both areas after the field-type correction. The [sample measurements](SOURCE-SIZES.md#lower-manhattan-2-km-comparison) retain full original responses and counts. The [2020 NYSDOT bridge inventory manual](https://www.dot.ny.gov/divisions/engineering/structures/repository/manuals/inventory/NYSDOT_inventory_manual_2020.pdf) defines its minimum vertical clearance for a crossed highway as the distance from the lowest permanent overhead obstruction to pavement directly below, excluding shoulders; for rail it uses top of rail. Its source coding uses separate feet/inches, `0 0` for a crossed feature that is neither highway nor rail, `99 12` for clearance above 100 feet but not unlimited, and `99 99` for unlimited. The live service publishes numeric fields rather than separate feet/inches columns; their exact mapping to this manual, edition and crossing direction have not been verified. Merge therefore retains service values and both original responses without conversion or interpreting zero/high values. A bridge point with a reported minimum cannot certify a continuous underside or safe travel clearance.

## Merge and rendering

The `transport-inventory` merge policy retains the roadway/ramp/bridge rows as complementary observations. The sign and height-restricted-bridge layers have separate `sign-structure-inventory` and `bridge-clearance-inventory` policies; neither uses proximity-only joins or promotes a reference point to a physical model. NYSDOT bridge BINs use a bridge namespace, separately from NYC building BINs. Federal NBI structure IDs require a verified mapping before they are joined to state bridge BINs. Equal names, nearby lines, shared route IDs or bridge identifiers alone do not prove that two records describe the same geometry, physical level or observation date. Unproven duplicates remain available. No inventory record replaces OSM node connectivity or the NYC deck/roadbed polygons. [FHWA warns](https://www.fhwa.dot.gov/bridge/nbi/ascii.cfm) that NBI values should not be used for route-clearance decisions; the map retains the reported values as qualified source fields only.

The current renderer shows alignments and inventory locations as references within the selected area. The sign points stay reference markers; neither source selection nor rendering makes a sign face, gantry or post from the point alone. It does not promote zero Z to an elevation, turn bridge points into columns, construct missing road links or derive a support layout from span counts. The existing bridge-grade rules still use compatible NYC bridge spot observations and actual OSM topology. Explicit future matching/render rules can use inventory fields after validating role, identity, direction, level, units and local geometry. Source data remains unchanged when those rules are added. The [Lower Manhattan source-size manifests](SOURCE-SIZES.md#lower-manhattan-2-km-comparison) include a live 11-record NBI export, all original attributes and native/GeoJSON responses; this is separate from any guessed pier layout.

These sources improve available ramp alignments and structural constraints; they do not close the measured support-location gap. The [source audit](SOURCE-FIDELITY-AUDIT.md#pillars-supports-and-elevated-structures) also covers OSM support mapping, original NYC XYZ and LiDAR. No public API locating every elevated train/highway column has been verified. Aerial returns must be inspected before claiming exposed support geometry, and do not certify hidden undersides.

The later [support-source review](SUPPORT-SOURCES.md) adds public NYSDOT pier/cap/footing drawings as potential renderer-template references. [MTA/NOAA acquisition](SOURCE-ACQUISITION.md) now collects actual station records and original LiDAR point payloads; complete LAS records are now decoded locally while modeling remains pending. Typical design drawings remain separate from measured geographic observations.

## Evidence and remaining work

The new acquisition is separate from the unchanged historical large crash capture. Full responses, request provenance and summaries are retained locally in `.tmp/map-lab/nysdot-investigation/` and `.tmp/map-lab/nysdot-adapter/`. Exact area bounds, dates and record counts live in those acquisition summaries, alongside their source values. The [pinned transport fixture](../tests/fixtures/transport-inventory-manifest.json) retains exact scoped records, full metadata, original batch requests, attribution and an uncompressed checksum; it is test input only.

[Transport inventory tests](../tests/transport-inventory-test.mjs) cover captured schemas, native/GeoJSON completeness, confirmed empty inventories, batch boundaries, all-field/Z/M retention, immutable exports, source roles, visibility and cancellation. [Browser regressions](../tests/transport-inventory-browser-test.mjs) verify reference rendering through the worker, full raw retention, separate merge decisions, Help and source toggles on the verified hardware Xvfb path. Direct live browser acquisition is preserved separately in the local evidence; it is not replaced by mocked regression results. Current scoped suite/audit reports are listed in [the fidelity review](REVIEW-FIDELITY-2026-09-28.md#verification-evidence). Broader on-ramp fidelity still needs full OSM interchange connectivity and compatible height evidence. Bridge support locations/dimensions and inventory field interpretation remain open. Walking is an inspection tool; further collision development is deferred.
